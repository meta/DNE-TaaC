# DNE-Taac

Test As A Config (TAAC) — a configuration-driven network test automation framework. TAAC provides a declarative approach to FBOSS network device testing, where test scenarios are expressed as structured configurations rather than imperative scripts.

A test is a `TestConfig` containing one or more **playbooks**; a playbook runs against a **DUT** (device under test) and is composed of ordered **stages**; each stage is a list of **steps** — the smallest units of work (e.g. `RUN_SSH_COMMAND_STEP`, `DUMMY_STEP`, plus device-management ones). Stages express ordering and parallelism; playbooks group what runs against which device.

## Repository layout

| Path | What lives there |
|---|---|
| `taac/thrift/taac/test_as_a_config.thrift` | The schema — source of truth for everything a test can express. |
| `taac/steps/`, `taac/stages/`, `taac/playbooks/` | Runtime implementations of the schema objects. |
| `taac/libs/taac_runner.py` | `TaacRunner` — setup → execute → teardown lifecycle. |
| `taac/runner/` | The OSS CLI — entry point, argument parsing, result formatting. |
| `taac/testconfigs/` | Shipped test configs, grouped by program (`oss/`, `routing/`, `fpf/`, `npi/`, …). |
| `taac/health_checks/` | Pre/post/snapshot check definitions. |
| `taac/ixia/`, `taac/otg/` | Traffic-generator backends. |
| `examples/` | Runnable examples + sample topology CSVs. |
| `docker/` | Image build + run wrappers — see [`docker/README.md`](docker/README.md). |
| `scripts/` | `validate.sh`, `run_tests.sh`, getdeps setup, `taac_run.sh`, `inspect_topology.sh`. |

## Quick start

Smoke-tested via [meta/fboss](https://github.com/meta/fboss)'s public Docker images on **CentOS Stream 9**. Docker is the only host-side dependency.

```bash
# Build the vendor-shippable TAAC image (auto-builds base image if missing)
./docker/build-taac-image.sh
```

That single command builds the FBOSS CentOS base image if missing, compiles the full dep tree (folly, fizz, wangle, mvfst, fbthrift), builds TAAC, and produces `fboss-taac` — a self-contained image with all transitive deps baked in.

The normal command reuses the revision-tagged FBOSS/Thrift base image and
unchanged TAAC layers. Use `--rebuild-taac-image` to rebuild TAAC without its
layer cache, `--rebuild-base-image` to refresh the compiler/runtime base, or
`--no-cache` as the compatibility shortcut for rebuilding both.

## Why TAAC runs in a container

TAAC is Python on top of a large native stack, so the container isn't packaging convenience — it's the only supported way to get a working install:

- The FBOSS thrift bindings (`neteng.fboss.*`, `taac.test_as_a_config.*`) are generated by `thrift1` and linked against fbthrift's native libraries. There is no wheel to pip-install.
- Their deps (folly, fizz, wangle, mvfst, fbthrift) are a from-source C++ build — ~22 min cold, and sensitive to host compiler and system library versions.
- The base image tag is derived from the fboss rev in `getdeps/manifests/fboss-thrift-defs`, so one commit supplies both the build environment and the thrift defs. Bindings can't silently drift from the agent they talk to.
- CentOS Stream 9 is the only smoke-tested platform; the container makes your distro irrelevant.
- It is what an OSS user runs. `docker run --rm fboss-taac python3 ...` needs no registry, credentials, or host-side state — the entrypoint exports `PYTHONPATH`, `LD_LIBRARY_PATH` and `TAAC_OSS=1`.

### `docker/run_taac_docker.sh`

Day-to-day wrapper so you don't retype bind mounts, `--network host`, and env forwarding:

```bash
./docker/run_taac_docker.sh                     # interactive shell in the container
./docker/run_taac_docker.sh --regen             # regenerate thrift bindings first, then shell
./docker/run_taac_docker.sh run <cmd...>        # run one command, non-interactive
./docker/run_taac_docker.sh --image my-taac:v1  # use a different image
./docker/run_taac_docker.sh --workspace <path>  # mount somewhere other than the repo root
./docker/run_taac_docker.sh -v /host:/ctr       # extra volume mount (repeatable)
```

It bind-mounts the repo at `/workspace` and prepends it to `PYTHONPATH`, so working-tree edits
shadow the baked-in `/taac` source — Python changes need no rebuild, and `--regen` extends that
to `.thrift` edits. It also runs `--network host` (internal-DNS hostnames resolve), mounts
`/tmp` through (logs and result files survive the container), and forwards every `TAAC_*` env
var, so secrets like `TAAC_SSH_PASSWORD` stay out of `bash -c` strings and shell history.

Rule of thumb: `build-taac-image.sh` when native deps or the fboss pin change; `run_taac_docker.sh` for everything else.

### Validating a change

To build *and* verify in one step — the entry point CI and contributors should use:

```bash
# Build the image, then run unit tests + smoke test against it
./scripts/validate.sh
```

Run it with no arguments and it needs no registry, no credentials, and no host-side
state beyond Docker. Useful variants:

```bash
./scripts/validate.sh --skip-smoke              # unit tests only, skip the smoke test
./scripts/validate.sh --skip-tests              # build the image, run no tests
./scripts/validate.sh --pull --image IMAGE      # test a prebuilt image instead of building one
./scripts/validate.sh --dry-run                 # print the commands, execute nothing
```

Anything after `--` is forwarded verbatim to pytest, so pytest's own selection flags
work unchanged — `-k` filters by test name, for example:

```bash
./scripts/validate.sh -- -k retry               # run only tests whose name matches "retry"
./scripts/validate.sh -- taac/runner/tests/ -v  # run one directory, verbosely
```

`validate.sh` composes the two scripts either side of it — `docker/build-taac-image.sh`
to acquire an image and `scripts/run_tests.sh` to test one — so either can still be
driven directly when you want just one half.

The image's entrypoint sets `PYTHONPATH` and `LD_LIBRARY_PATH` automatically, so vendors can `docker run --rm fboss-taac python3 ...` with no host-side state. See [`docker/README.md`](docker/README.md) for the build-flow diagram and layer-cache contract.

For iterative work on TAAC source or thrift schemas in a bind-mounted workspace — no image rebuild required — see the in-container iteration section in [`docker/README.md`](docker/README.md) (Python source edits work via `PYTHONPATH`; thrift edits use the baked-in `taac-regen-thrift` helper).

### Build cost

First build takes ~22 min cold (mostly the deps compile). Docker's layer cache makes subsequent rebuilds after TAAC-only source changes finish in ~30 sec. See [`docker/README.md`](docker/README.md) for the layer cache contract and when to rebuild what.

## How a TAAC test is structured

Every object is a thrift struct in
[`taac/thrift/taac/test_as_a_config.thrift`](taac/thrift/taac/test_as_a_config.thrift). A test
is a Python file that builds one — no pytest collection, no base class, no imperative test body.

```
TestConfig                      # the unit you pass to --test-configs
├── name, endpoints, host_os_type_map
├── setup_tasks / teardown_tasks
└── playbooks[]                 # named scenarios
    ├── setup_steps / cleanup_steps
    ├── prechecks / postchecks / snapshot_checks
    ├── periodic_tasks
    └── stages[]                # ordering + parallelism
        └── steps[]             # the actual units of work
            └── step_params     # per-step inputs
```

**`TestConfig`** is the whole test and the unit you hand to the runner. It names the test,
declares which devices take part and what OS each runs, and carries everything that applies
test-wide — setup and teardown tasks, logging configuration, traffic-generator setup, and the
health checks that gate the run before it starts.

**`Playbook`** is one named scenario inside the config, and the unit the runner iterates over.
It owns its own setup and cleanup, the health checks taken before and after it, any background
tasks polled while it runs, and filters that restrict it to a subset of the devices. Playbooks
can be disabled in place or repeated, so a config can carry more scenarios than any single run
executes.

**`Stage`** is the ordering primitive within a playbook. Stages run one after another, and each
stage decides whether its own contents run sequentially or in parallel, how many times to
repeat, and whether to abandon the rest of the stage once something fails.

**`Step`** is the smallest unit of work — one action against one device, such as running a
command, restarting a service, flapping an interface, or injecting routes. Each step carries
its own parameters, optional retry behaviour, and optional delay. Parameters can be static
values or pulled from earlier steps, which is how a step consumes what a previous one produced.

The full vocabulary of steps and every field on these structs lives in the thrift file.
[`examples/live_smoke_config.py`](examples/live_smoke_config.py) is a small working config.

## Running tests: the OSS entry point

`taac.runner.oss_entry_point` is the CLI for running TAAC outside Meta. It loads your test
configs, builds a topology from your CSVs, drives `TaacRunner` through setup → execute →
teardown, and writes out results. Every selected playbook runs against every `--dut`.

```bash
./docker/run_taac_docker.sh run \
    python3 -m taac.runner.oss_entry_point \
        --test-configs examples/live_smoke_config.py \
        --device-info-csv examples/topology/sample_device_info.csv \
        --circuit-info-csv examples/topology/sample_circuit_info.csv \
        --dut switch1.example.com \
        --skip-post-setup-wait
```

### Arguments

The example above uses the flags you need for a typical run:

| Argument | Meaning |
|---|---|
| `--test-configs PATH…` *(required)* | One or more `.py` test-config files. Each must export a `TestConfig` (or a factory returning one) under a recognised name. |
| `--dut HOST…` *(required, alias `--device`)* | Devices under test. Any DUT not already declared in the config is added automatically, so configs can ship without hardcoded hostnames. |
| `--device-info-csv PATH` | Your fleet's device list — hostname to OS, role, and vendor. |
| `--circuit-info-csv PATH` | Your link list; used to build the topology the test runs against. Sample CSVs for both flags live in `examples/topology/` — copy them and substitute your own hostnames. |
| `--skip-post-setup-wait` | Skip the 180 s interface-stabilization sleep after setup. Wanted against already-up devices you aren't rebooting. |

Beyond these there are flags for playbook selection, IXIA setup, skipping setup/teardown,
timeouts and retries, log level, and JSON / JUnit result output. Run the entry point with
`--help`, or see [`taac/runner/README.md`](taac/runner/README.md) for the full reference.

## Traffic generation: IxNetwork today, OTG in progress

TAAC is IxNetwork-native: `TrafficGeneratorBackend` defaults to `RESTPY`, meaning most
traffic-driving tests expect a real IXIA chassis reachable via `--ixia-api-server` and will
not start without one. Non-traffic tests (SSH-driven playbooks, health checks, `--dry-run`)
are unaffected.

There's ongoing work to migrate onto the vendor-neutral [OTG](https://github.com/open-traffic-generator)
model via [snappi](https://github.com/open-traffic-generator/snappi), which can run against
ixia-c containers or hardware chassis without an IxNetwork dependency. Opt in per test with
`traffic_generator_backend=TrafficGeneratorBackend.OTG` on the `TestConfig`; see
[`taac/otg/README.md`](taac/otg/README.md) for the architecture and
[`taac/otg/MIGRATION.md`](taac/otg/MIGRATION.md) for what moving an existing chassis over
involves. Not every restpy-based test has an OTG equivalent yet.

## Outputs

Inside the `fboss-taac` image, generated thrift bindings + the TAAC Python source land under:

```
/scratch/installed/taac-<HASH>/lib/python3/site-packages/
```

They contain `taac/`, `ixia/`, `neteng/`, `facebook/`, `fb303/`. Each generated `thrift_types.py` ships a co-located `types.py` / `ttypes.py` / `clients.py` shim so legacy-style imports resolve.

The `<HASH>` suffix is getdeps' per-configuration cache key — it changes if you pass different `--extra-cmake-defines` to `getdeps.py build`.

## Using the bindings

The image's entrypoint automatically sets `PYTHONPATH` and `LD_LIBRARY_PATH`, so imports work out of the box:

```bash
docker run --rm fboss-taac python3 -c '
    from neteng.fboss.ctrl.thrift_types import NdpEntryThrift
    from taac.test_as_a_config.thrift_types import TestConfig
    print("ok")
'
```

## Running TAAC modules under OSS

TAAC's Python modules (e.g. `taac.libs.taac_runner`) include Meta-internal imports that aren't shipped in this slice. Set `TAAC_OSS=1` so the imports take their OSS branch:

```bash
export TAAC_OSS=1
python3 -c 'import taac.libs.taac_runner; print("ok")'
```

The image entrypoint and `run_taac_docker.sh` set it for you.

Some runtime functionality is stubbed in OSS mode (NDS drainer, COOP patcher, ValidationStep, AristaSSHHelper, etc.) and will raise `NotImplementedError` if invoked on a code path that requires it. Imports succeed; trying to actually use those features fails.

### Driving a minimal test

```python
import asyncio
from taac.test_as_a_config.thrift_types import (
    TestConfig, Playbook, Stage, Step, StepName, Endpoint, DeviceOsType,
)
from taac.libs.taac_runner import TaacRunner

cfg = TestConfig(
    name='smoke',
    basset_pool='',  # Meta-internal hardware reservation pool; '' is fine for OSS
    playbooks=[Playbook(
        name='dummy_playbook',
        stages=[Stage(steps=[Step(name=StepName.DUMMY_STEP)])],
    )],
    endpoints=[Endpoint(name='your-host', dut=True)],
    host_os_type_map={'your-host': DeviceOsType.FBOSS},
    startup_checks=[],
)

# skip_post_setup_wait skips a 180s interface-stabilization sleep
# that's only useful when booting real hardware.
async def main():
    runner = TaacRunner(test_config=cfg, skip_post_setup_wait=True)
    await runner.async_test_setUp()
    await runner.run_tests()

asyncio.run(main())
```

### Live-device smoke

`examples/live_smoke_config.py` runs the same shape against real device(s) — a `DUMMY_STEP`
playbook, a `RUN_SSH_COMMAND_STEP` playbook, and a collector playbook. It needs `TAAC_OSS=1`,
`TAAC_SSH_USER`, and `TAAC_SSH_PASSWORD` on the host; `run_taac_docker.sh` forwards any
`TAAC_*` env var into the container, so keep secrets out of inline `bash -c` strings:

```bash
# Source the password from a file (chmod 600), not the command line.
export TAAC_OSS=1 TAAC_SSH_USER=netops
source ~/.taac-secrets  # exports TAAC_SSH_PASSWORD=...

./docker/run_taac_docker.sh run \
    python3 -m taac.runner.oss_entry_point \
        --test-configs /workspace/examples/live_smoke_config.py \
        --device-info-csv /workspace/examples/topology/sample_device_info.csv \
        --circuit-info-csv /workspace/examples/topology/sample_circuit_info.csv \
        --dut <hostname> \
        --skip-post-setup-wait
```

`examples/topology/` ships sample CSVs as templates — copy them, replace the placeholder hostnames / OS column with your own fleet, and point `--device-info-csv` / `--circuit-info-csv` at your copies.

### Plugging in a custom driver

`DEVICE_OS_DRIVER_CLASS_MAP` ships with `FbossSwitch` registered for `DeviceOsType.FBOSS`. For other OS types (Arista, Cisco, etc.), register your own `AbstractSwitch` subclass:

```python
from taac.utils.driver_factory import register_driver_class
from taac.test_as_a_config.thrift_types import DeviceOsType
from my_pkg.my_driver import MyArista  # your subclass of AbstractSwitch

register_driver_class(DeviceOsType.ARISTA_OS, MyArista)
```

## Troubleshooting

| Symptom | Likely cause |
|---|---|
| `ModuleNotFoundError` for `neteng.*` / `taac.test_as_a_config` | Running outside the image, or bypassing the entrypoint. Use `run_taac_docker.sh`. |
| `NotImplementedError` from a step or helper | That path is stubbed in OSS mode — see above. |
| `No test config found in <path>` | The module exports none of `test_config` / `TEST_CONFIG` / `config` / `CONFIG`. |
| `No playbooks found to execute` | Every playbook is `enabled=False`, or `--playbook` named one that is. |
| `<host> not found in topology` | The DUT isn't in `endpoints` and isn't resolvable from `--device-info-csv`. |
| `.thrift` edits appear to do nothing | Bindings are baked into the image — re-enter with `--regen`, or rebuild. |
| Topology looks stale mid-run | The OSS loader memoizes on first read; pass the CSVs via CLI flags, not late env exports. |

`scripts/inspect_topology.sh` (a wrapper around `python3 -m taac.runner.inspect`) prints the endpoints, Ixia ports and playbooks a `TestConfig` requires, without contacting any device.
